# 设计与调试铁律（17 条）

`global-rules.md` 只常驻最常踩的几条，其余细则放这里，需要时再读。本文件随安装复制到 `~/.dsh/rules-design.md`。

## 设计

1. **先删减，再少量新增。** 先删除无用代码和过期检查，再做能工作的最短 diff；不为只有一个使用者的代码做抽象。适用于评估 diff 规模或想加层次时。
2. **数据形态优先。** 先选核心类型和结构，再写逻辑。适用于写新逻辑之前。
3. **对领域建模。** 状态放进一个结构（可辨识联合、状态机、查找表），而不是散在各处的条件判断。适用于分支很多，或同一结构跨文件重复出现时。
4. **围绕新需求重新设计。** 新需求进来时，让设计仿佛从第一天起就已存在。适用于新功能让现有设计变得牵强时。
5. **降低读者负担。** 内联只有一个调用方的包装函数，缩小可变状态的作用范围。适用于代码难以追踪时。
6. **在边界设防。** 在输入进入系统之处（CLI、配置、网络、文件、外部 API）校验；系统内部信任类型，核心逻辑保持纯粹。适用于加校验或错误处理时。
7. **步骤幂等。** 重复运行一步，即使崩溃后重跑也到达同一状态。适用于命令、环境搭建和重试。
8. **避免共享写入者。** 用锁之前，先让每个并发执行者拥有自己的文件、分支或键。适用于并行工作触及共享状态时。
9. **先迁移，再删除。** 一次改动里迁移全部调用方并删掉旧 API，不留兼容层。适用于替换 API 或分阶段重写时。
10. **比较方案。** 全新的设计先勾 2–3 个方案，优先数量更少但打磨完善的功能。适用于新架构、新体验或范围取舍。

## 调试与验证

11. **解决根本原因。** 在状态首次出错的位置修；防护逻辑只处理合法状态。适用于调试时。
12. **检验前提。** 两次失败的修复基于同一假设时，把假设写下来直接检验。适用于第三次尝试之前。
13. **证明它有效。** 跑真实对象、读真实输出，不依赖替代指标。适用于宣布完成之前。
14. **可验证的单元。** 把工作拆成多个步骤，每步以通过的检查收尾。适用于批量处理、迁移和叠放提交。
15. **测试行为。** 断言调用方可观察的结果，让测试经得起重构。适用于写或留测试时。
16. **解释数字。** 找出测量受什么限制，确认量的是正确的工作。适用于基准测试和评分。
17. **构建工具。** 批量或重复工作写成脚本，方便重复运行。适用于大量编辑或检查。
